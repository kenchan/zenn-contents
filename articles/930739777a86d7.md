## 複数のTeamにまたがるArtifact共有の課題

GMOペパボでは、部門単位でClaudeのTeamプランを契約しています。理由はいくつかありますが、一番大きいのはTeamプランの上限人数が150人(2026年9月時点)であることです。

Claude CodeのArtifactツールは、作成したHTMLをclaude.ai上でホストして公開できます。公開範囲は「自分だけ」「組織内の特定のメンバー」「組織内の全員」「インターネットに公開」から選べますが、組織をまたいで見せる方法はインターネットへの公開しかありません。社内では、意図せず全世界に公開されることを防ぐため「インターネットに公開」はできないように設定しています。その結果、Teamをまたいでほかの部門のメンバーにHTMLを見せることができなくなっていました。

そこで、Teamに関係なくHTMLを共有できる仕組みとして、`share-html`というプラグインを社内用のマーケットプレイスで配布しています。しかし、プラグインのインストールを徹底できておらず、「Artifactが見えません」というやりとりがたびたび発生していました。

この状況を改善するために、2つの設定を配布することにしました。1つは`share-html`を全員に自動インストールする設定、もう1つはArtifactによる公開を試みたときに`share-html`を使うようClaude Codeを誘導する設定です。

## プラグインを強制的にインストールする

ClaudeのTeamプランやEnterpriseプランには、claude.aiの管理画面から全メンバーのClaude Codeに設定を配布する仕組み(managed-settings)があります。ここで`extraKnownMarketplaces`に社内マーケットプレイスを登録し、`enabledPlugins`で`share-html`を有効にします。これで、全メンバーの環境に`share-html`が自動でインストールされます。

```json
{
  "extraKnownMarketplaces": {
    "internal-tools": {
      "source": { "source": "git", "url": "<社内のプラグインマーケットプレイスのURL>" }
    }
  },
  "enabledPlugins": {
    "share-html@internal-tools": true
  }
}
```

## PreToolUseフックでArtifactの代わりに社内ツールを使わせる

Artifactでの公開を止めるにはPreToolUseフックを使います。PreToolUseフックはツールの実行直前に呼ばれ、標準出力で返した判定によってツールの実行を止めることができます。Artifactツールの呼び出しをdenyし、denyの理由として`share-html`を使うよう書いておけば、モデルはそのメッセージを読んで代替手段を知ることができます。

Artifactツールが何をしているのかを確認すると、HTMLの生成と編集はWriteツールとEditツールが行い、最後に公開する部分だけを担っていることがわかりました。そのため、Artifactツールの呼び出しをすべてdenyしてもよいだろうと考えました。

```json:~/.claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Artifact",
        "hooks": [
          {
            "type": "command",
            "command": "echo '{\"hookSpecificOutput\":{\"hookEventName\":\"PreToolUse\",\"permissionDecision\":\"deny\",\"permissionDecisionReason\":\"社内ではArtifactでの公開は使わない方針です。HTML作成はそのまま進め、公開はshare-htmlのような社内共有ツールを使ってください。\"}}'"
          }
        ]
      }
    ]
  }
}
```

`hookSpecificOutput`に`permissionDecision`と`permissionDecisionReason`を返す形式です。詳細はClaude Codeの[Hooksのドキュメント](https://code.claude.com/docs/ja/hooks)を参照してください。実際にArtifactで公開を試みると、期待どおりdenyされ、`permissionDecisionReason`の文章がそのままモデルに返りました。

## Artifactツールそのものは無効化しない

Artifactツール自体を無効化する設定を配布する案もありました。しかし、ツールを無効化するとArtifactはツールリストから消え、呼び出しそのものが発生しなくなります。そうすると、Claude Codeが公開用のHTMLを作成するプロセスそのものが変わり、途中で意図しないツールやサービスを利用するリスクが高まると考えました。そのため、Artifactツールはそのまま有効にして、フックで解決する方法を採用しました。

## まとめ

Teamをまたいだ共有にArtifactを使えないという制約を、managed-settingsによるプラグインの自動インストールと、PreToolUseフックによる誘導の2つで解消しました。ツールを無効化するのではなくフックでdenyすることで、モデル自身に代替手段を伝えられることが確認できました。
