Claude CodeのようなAIエージェントにコードを書かせて、そのままコミットまで任せることが増えました。このとき、Gitのauthorとcommitter、そしてコミットの署名はどうあるべきでしょうか。私は、committerをClaude Codeにして、Claude Codeがするコミットには署名しないことにしています。

## authorとcommitter

Gitのコミットには、authorとcommitterの2つの情報があります。[Pro Git](https://git-scm.com/book/ja/v2/Git-%E3%81%AE%E5%9F%BA%E6%9C%AC-%E3%82%B3%E3%83%9F%E3%83%83%E3%83%88%E5%B1%A5%E6%AD%B4%E3%81%AE%E9%96%B2%E8%A6%A7)では次のように説明されています。

> authorとはその作業をもともと行った人、committerとはその作業を適用した人のことを指します。

## committerはClaude Codeにする

Claude Codeがコミットしたのであれば、その作業を適用したのはClaude Codeです。作業をしたのはAIですが、責任は自分が持ちます。そのことをコミットに残すために、committerをClaude Codeにしています。

一方で、authorはどちらでもいいと考えています。今回の設定ではauthorは変えていないので、自分のままです。

## Claude Codeがするコミットには署名しない

コミットの署名は、コードを書いた人ではなくコミットをした人の証明です。Claude Codeがしたコミットに自分の鍵で署名すると、自分がコミットしたことになってしまいます。そのため、自分のターミナルからのコミットは今までどおり1PasswordのSSH鍵で署名し、Claude Codeがするコミットだけは署名しないようにしています。

## Co-Authored-Byと併用する

Claude Codeは標準で、コミットメッセージに`Co-Authored-By: Claude ...`のtrailerを付けます。trailerはどのモデルが関わったかを、committerは誰がコミットしたかを表すもので、役割が違います。そのため両方を使っています。

## 設定

`~/.claude/settings.json`の`env`に次を追加します。

```json:~/.claude/settings.json
{
  "env": {
    "GIT_COMMITTER_NAME": "Claude Code",
    "GIT_COMMITTER_EMAIL": "claude-code@anthropic.localhost",
    "GIT_CONFIG_COUNT": "1",
    "GIT_CONFIG_KEY_0": "commit.gpgsign",
    "GIT_CONFIG_VALUE_0": "false"
  }
}
```

`env`に書いた環境変数は、Claude Codeが起動するプロセスにだけ渡されます。そのため、Bashツールから実行するgitにだけこれらの設定が効きます。なお、`env`はClaude Codeを再起動するまで反映されません。

### `GIT_COMMITTER_NAME`と`GIT_COMMITTER_EMAIL`

[gitのドキュメント](https://git-scm.com/docs/git)によると、`GIT_COMMITTER_NAME`は`user.name`と`committer.name`の設定を、`GIT_COMMITTER_EMAIL`は`user.email`と`committer.email`の設定を上書きします。authorの環境変数(`GIT_AUTHOR_NAME`など)は設定していないので、authorは`user.name`と`user.email`のままです。

### `GIT_CONFIG_COUNT`と`GIT_CONFIG_KEY_<n>`、`GIT_CONFIG_VALUE_<n>`

`commit.gpgsign`のような任意の設定を環境変数で上書きするには`GIT_CONFIG_COUNT`を使います。`GIT_CONFIG_COUNT`に正の数を入れると、その数だけ`GIT_CONFIG_KEY_<n>`と`GIT_CONFIG_VALUE_<n>`の組が実行時の設定として追加されます。`<n>`は0から始まります。

[git configのドキュメント](https://git-scm.com/docs/git-config)では、これらの環境変数は`git -c`と同じcommandスコープに入り、設定ファイルの値を上書きすると書かれています。ただし、`git -c`で明示的に渡した値のほうが優先されます。

この環境変数はGit 2.31.0で追加されました。[リリースノート](https://github.com/git/git/blob/master/Documentation/RelNotes/2.31.0.adoc)には、環境変数で設定を渡す方法が2つ追加されたと書かれています。

### 確認する

Claude CodeのBashツールで、実際に効いている値を確認します。

```console
$ git config --show-scope --show-origin commit.gpgsign
command	command line:	false
$ git var GIT_COMMITTER_IDENT
Claude Code <claude-code@anthropic.localhost> ...
$ git var GIT_AUTHOR_IDENT
Kenichi Takahashi <...> ...
```

`commit.gpgsign`がcommandスコープで`false`になり、committerだけがClaude Codeに変わっています。

## まとめ

- committerは作業を適用した人なので、Claude CodeがするコミットのcommitterはClaude Codeにする
- コミットの署名はコミットをした人の証明なので、Claude Codeがするコミットには自分の鍵で署名しない
- authorはどちらでもいい
- `Co-Authored-By`のtrailerはcommitterとは役割が違うので併用する
- 設定は`~/.claude/settings.json`の`env`で、Claude Codeが起動するgitにだけ効かせられる
